# CLAUDE.md

Обязательное чтение в начале каждой сессии разработки:

1. **`00_PROJECT_BRIEF.md`** — концепция продукта, целевая аудитория, бизнес-модель
2. **`01_TECHNICAL_SPEC.md`** — полное ТЗ, архитектура, стек, roadmap
3. **`02_CLAUDE_PROMPT.md`** — системный промт: правила работы, стек, код-стайл, процесс

Язык общения с пользователем: русский. Язык кода и документации: английский.

Стек: TypeScript монорепо (pnpm + Nx), NestJS + Prisma + PostgreSQL + Redis на бэке, Angular 21+ со standalone и signals на фронте (web / TMA / admin / KDS), Flutter в v2 для iOS/Android. Платежи — Stripe в текущем коде; идёт замена на банковский эквайринг, документацию присылает заказчик. До неё платёжный фронтенд не трогаем.

## Автономность

Работать самостоятельно, без запросов на подтверждение. Коммиты, рефакторинг, добавление и обновление зависимостей, миграции — делать сразу, не спрашивая. Пушить в назначенную ветку по мере готовности блоков; pull request открывать только по явной просьбе.

Спрашивать только там, где ответ меняет сам результат работы: неоднозначные продуктовые требования, выбор между вариантами с разными последствиями для пользователя, доступ к внешним системам. Технические решения внутри поставленной задачи принимать самому и коротко сообщать, что выбрано и почему.

Исключение — необратимое и выходящее наружу: force-push в общие ветки, удаление данных, отправка чего-либо клиентам или в сторонние сервисы. Это по-прежнему согласовывать.

При значимом изменении (новая фича, фикс с пользовательским эффектом, обновление стека/инфры) — параллельно:

- Записывать строку в `docs/CHANGELOG.md` под `[Unreleased]` (формат Keep a Changelog).
- Если меняется модель данных, API или стек — синхронизировать соответствующие разделы `01_TECHNICAL_SPEC.md`.
