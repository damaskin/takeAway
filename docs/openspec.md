# OpenSpec

[OpenSpec](https://github.com/Fission-AI/OpenSpec) (MIT) — план фичи в файлах, который агент пишет до кода, а Raynor ревьюит. После реализации требования из плана вливаются в постоянные спецификации `openspec/specs/`, и следующие сессии читают, как система должна себя вести, а не выясняют это заново по коду.

## Когда брать

- Фича или изменение поведения, которое затрагивает несколько поверхностей: API и хотя бы один клиент (web, TMA, admin, mobile).
- Фича, которую будут делать параллельные агенты в разных worktree.
- Неочевидное продуктовое поведение, которое стоит согласовать до кода.

Не брать для багфикса, правки текста, обновления зависимостей, релизных и CI-задач — там хватает обычного плана (EnterPlanMode).

## Цикл

| Шаг         | Claude Code / Cursor       | Codex                      | Что происходит                                                                                                   |
| ----------- | -------------------------- | -------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Разобраться | `/openspec-explore`        | `$openspec-explore`        | Агент читает код и обсуждает варианты, ничего не пишет.                                                          |
| План        | `/openspec-propose <идея>` | `$openspec-propose <идея>` | `openspec/changes/<имя>/`: `proposal.md`, `specs/` (дельты требований), `design.md`, `tasks.md`. Код не трогает. |
| Ревью       | —                          | —                          | Raynor читает план, правки — словами или `/openspec-update-change`.                                              |
| Реализация  | `/openspec-apply-change`   | `$openspec-apply-change`   | Задачи из `tasks.md` по порядку, с отметками `[x]`.                                                              |
| Архив       | `/openspec-archive-change` | `$openspec-archive-change` | Дельты вливаются в `openspec/specs/<capability>/spec.md`, папка изменения уходит в `changes/archive/`.           |

Реализацию лучше начинать в новой сессии: план уже в файлах, а чистый контекст авторы OpenSpec прямо советуют.

## Правила проекта для планов

Лежат в `openspec/config.yaml` и подмешиваются в каждую инструкцию агенту. Главное:

- Артефакты — на английском, как вся документация.
- Capability называется по модулю API, который владеет поведением (`orders`, `catalog`, `payments`, `kitchen`…), а не по приложению.
- Спецификации пишутся только на то, что меняется. Задним числом существующее не описываем.
- `tasks.md` разбит по поверхностям (API, Libs, Admin, Web, TMA, Mobile, Docs): каждому параллельному агенту — своя группа, API и libs первыми. Последняя группа — строка в `docs/CHANGELOG.md` и разделы `01_TECHNICAL_SPEC.md`, если меняются модель данных, API или стек.
- Архивировать в той же ветке, что и код, до мержа PR — тогда спецификации на `main` описывают код на `main`.

`01_TECHNICAL_SPEC.md` остаётся обзором архитектуры, модели данных и дорожной карты; `openspec/specs/` — поведение по capability, растущее изменение за изменением.

## Где что лежит

- `openspec/` — конфиг, спецификации, изменения в работе и архив. Коммитится.
- `.agents/skills/openspec-*` — скиллы для Codex и Cursor.
- `.claude/skills/openspec-*` — те же скиллы для Claude Code: обычные копии, а не ссылки (на Windows без режима разработчика ссылка не создаётся, а копия переживает git и облачные сессии).

Оба каталога скиллов генерирует OpenSpec, руками их не правим, prettier их не трогает (`.prettierignore`). `pnpm skills:update` обновляет только Angular-скиллы из `skills-lock.json`, скиллы OpenSpec он не задевает.

## CLI на каждой машине

Скиллы вызывают команду `openspec`, поэтому CLI нужен везде, где работает агент (этот ПК, Mac mini, облачная сессия):

```bash
npm install -g @fission-ai/openspec@2.0.0
```

```bash
openspec config set telemetry.enabled false
```

Нужен Node 22.12+. Версия зафиксирована: проект быстро меняется (2.0 убрала команды `/opsx:*`).

## Обновление

Обновить CLI до новой версии, затем в корне репозитория:

```bash
openspec update --dry-run
```

```bash
openspec update
```

`update` перегенерирует скиллы в обоих каталогах и чистит то, что оставили старые версии. Дифф стоит просмотреть перед коммитом, а версию в этом файле — поправить.
