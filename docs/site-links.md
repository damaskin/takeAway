# Ссылки сайта: соцсети и приложение

Куда сайт takeaway.md ведёт наружу — профили takeAway в соцсетях (иконки в подвале главной) и приложение в магазинах (страница `/app`, кнопки магазинов, редирект с телефона). Всё задаётся в одном файле: `apps/web/src/app/core/config/site-links.ts`, объект `SITE_LINKS`.

Это публичные значения, одинаковые для всех окружений, поэтому они в коде, а не в `.env` деплоя (как адреса и ключи в `index.html`). Поменять — коммит в этот файл и обычный деплой сайта.

**Пустое значение прячет то, что из него строится**: нет адреса Instagram — нет иконки, нет id App Store — нет кнопки App Store и редиректа айфонов. Ничего на сайте не ведёт в никуда.

## Соцсети — `SITE_LINKS.social`

| Поле        | Что вписать                      | Пример формата                        |
| ----------- | -------------------------------- | ------------------------------------- |
| `instagram` | полный адрес профиля             | `https://instagram.com/<имя>`         |
| `telegram`  | канал или чат takeAway (не бот!) | `https://t.me/<канал>`                |
| `tiktok`    | полный адрес профиля             | `https://www.tiktok.com/@<имя>`       |
| `facebook`  | страница                         | `https://www.facebook.com/<страница>` |
| `vk`        | сообщество                       | `https://vk.com/<сообщество>`         |

Учитываются только адреса, начинающиеся с `https://`. Иконки показываются в подвале главной в этом порядке, открываются в новой вкладке (`target="_blank" rel="noopener"`). Сейчас все пустые — подвал без иконок.

В `telegram` — публичный канал или чат, а не @takaway_tgbot: бот только присылает уведомления о заказах и не читает сообщения.

## Приложение — `SITE_LINKS.apps`

| Поле           | Откуда взять                                                                                                                                     | Сейчас            |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------- |
| `googlePlayId` | `applicationId` в `apps/mobile/android/app/build.gradle.kts` (тест сверяет)                                                                      | `md.takeaway.app` |
| `appStoreId`   | App Store Connect → приложение → App Information → **Apple ID** (цифры; то же, что после `id` в адресе витрины `https://apps.apple.com/app/id…`) | пусто             |

`takeaway.md/app` — одна ссылка на приложение для плакатов, тейбл-тентов и сообщений:

- Android-телефон сразу уходит в Google Play;
- iPhone/iPad — в App Store, когда `appStoreId` заполнен; пока он пустой, айфон остаётся на странице с предложением заказать на сайте;
- компьютер видит страницу с кнопками магазинов и QR-кодом `https://takeaway.md/app` (`apps/web/public/app-qr.svg`).

Сайт без серверного рендеринга, поэтому редирект делает страница при загрузке (`location.replace`, кнопка «Назад» из магазина не возвращает на редирект).

### Когда появится id App Store

1. Вписать его в `appStoreId`.
2. Добавить в `apps/web/src/index.html` рядом с другими `apple-*` мета-тегами баннер Smart App Banner для Safari:
   `<meta name="apple-itunes-app" content="app-id=<id>" />`.
   Safari читает его только из HTML при загрузке, поэтому из кода приложения его не добавить. Тест `site-links.spec.ts` падает, если id и баннер расходятся.

### QR-код

`apps/web/public/app-qr.svg` — QR ссылки `https://takeaway.md/app`, сгенерирован один раз и закоммичен (без зависимостей в сборке). Адрес не меняется, перегенерировать не нужно; если всё же понадобится:

```bash
python -c "import segno; segno.make('https://takeaway.md/app', error='m').save('apps/web/public/app-qr.svg', kind='svg', scale=1, border=2, dark='#000', light='#fff', xmldecl=False, omitsize=True, title='https://takeaway.md/app')"
```
